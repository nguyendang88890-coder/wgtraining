# WG Training Portal

Training portal cho nhân viên WeGolden (bản Global, thương hiệu WeGolden — không phải WeMasterTrade). Static HTML/CSS/JS thuần, không build step — backend là Firebase Realtime Database (project `wgtraining-a669d`, **độc lập** với project Firebase của web WMT cũ (`wmt-training-portal`, có ~140 user thật của web khác) — không bao giờ trỏ nhầm hoặc migrate dữ liệu giữa 2 project này).

- **Xác thực = Firebase Auth email + mật khẩu** (không còn Anonymous Auth, không còn mật khẩu/hash trong database, không có tự đăng ký). Chuỗi nhận diện: Auth `uid` → `uidmap/<uid>` = username → `users/<username>` (role, isLeader, leaderName...). Tài khoản chỉ do admin tạo (`admin.html` → Add User dùng `createAuthAccount`, ghi `uidmap` + profile nguyên tử rồi mới commit). Quên/đặt lại mật khẩu: email reset của Firebase (`sendResetEmail`) — admin **không xem được** mật khẩu, đừng thêm tính năng lưu/hiện mật khẩu dạng rõ.
- `firebase-config.js`: cấu hình Firebase (chọn môi trường: không phải localhost → prod; localhost → **staging** `wgtraining-staging` mặc định, đổi sang prod bằng `localStorage.wg_env='prod'`, có badge "STAGING DATA") + auth helpers (`getSession`, `requireSession`, `loginWithEmail`, `logoutUser`, `changeOwnPassword`...) + lớp đồng bộ `localStorage` ⇄ Firebase (`dbWrite`, `dbRemove`, `fbUpdate`, `syncFromFirebase` theo role: trainee chỉ tải dữ liệu của mình, leader thêm team, mod/admin rộng hơn). Đọc dữ liệu ở phía app qua `localStorage`; ghi qua `window.dbWrite`/`window.dbRemove`/`window.fbUpdate`; quyền thật nằm ở Security Rules, **không tin `localStorage`/role phía client**.
- **Security Rules**: sinh từ `firebase/build-rules.js` → `firebase/database.rules.json` (deny-by-default). Sửa rules = sửa `build-rules.js`, chạy `node firebase/build-rules.js`, chạy bộ test tấn công `node tools/rules-test/run.js` (chỉ chạy được trên staging, phải 141/141 đạt), deploy staging trước (`npx firebase-tools deploy --only database --project staging`), prod sau (`--project prod`). Bản rules cũ (trước migrate) lưu ở `C:\Users\T490\wg-backups\` (ngoài repo, không commit).
- `module-common.js`: logic & UI dùng chung (sidebar, quiz engine MCQ, chuông thông báo, feedback gate...) cho hầu hết các trang — nạp sau `firebase-config.js`.
- 6 module đào tạo: `module1.html` (Overview) → `module5.html` (Deposit & Withdrawal, gồm cả Savings Feature) → `module6.html` (KPI & Compensation, **hai bản riêng Anh và Việt** (mỗi đoạn có cặp `<span class="en">`/`<span class="vi">`, nút English / Tiếng Việt chuyển qua lại, không có chế độ hiện cả hai; quiz của trang này bật `window.QUIZ_BILINGUAL = true` để các thông báo của bộ quiz cũng đổi theo ngôn ngữ, các module khác không bị ảnh hưởng), tóm tắt "Cẩm nang KPI WeGolden" tại https://auditorwmt.github.io/Training-KPI-WEGOLDEN/). Mỗi module có mini-quiz **trắc nghiệm** (giữ nguyên MCQ), qua quiz ≥ 60% thì module tự hoàn thành, và **phải xong đủ cả 6 module mới được thi Final Exam**. Số module nằm ở một hằng số duy nhất `MODULE_COUNT` trong `firebase-config.js` (đừng viết cứng "5"/"6" ở nơi khác); thêm module mới thì cập nhật hằng số đó, `getSidebarHTML` + `_MOD_PAGE_MAP` trong `module-common.js`, sidebar và mảng `MODULES` trong `index.html`, và các tên module trong `exam.html`. Khi nội dung quiz đổi, bump tham số phiên bản trong `new ModuleQuiz(n, questions, 'phiên-bản')` để kết quả đã nộp ở bản cũ không bị chấm review sai.
- **Cache `localStorage` có lớp bảo vệ dung lượng** (đầu `firebase-config.js`): giá trị lớn của khóa `wmt_*` được nén tự động bằng lz-string (code vẫn dùng `localStorage.getItem/setItem` với JSON thường, không cần đổi); khi đầy bộ nhớ thì tự bỏ bớt cache có thể tải lại (tháng cũ nhất trước, không bao giờ bỏ dữ liệu của người đang đăng nhập hay cài đặt cục bộ như `wmt_gemini_key`, `wmt_notif_prefs_*`) rồi ghi lại thay vì ném lỗi. `dbWrite` luôn đẩy lên Firebase kể cả khi cache cục bộ lỗi. Gõ `lsStats()` ở console để xem mức dùng. Khóa `wmt_*` mới lưu dữ liệu per-user phải được thêm vào `tierOf` (lớp bảo vệ) và `_pruneOrphanCaches` (dọn khóa mồ côi) nếu dữ liệu đó tải lại được từ Firebase.
- **Monthly Test** lấy câu hỏi từ file Excel/CSV admin tải lên (node `qbank/bdcs` và `qbank/others`, cột Question, Type, A–D, Answer, Points, Liet, Rubric), **không nằm trong code**. File câu hỏi có đáp án không được commit vào repo công khai.
- **Final Exam (`exam.html`) là dạng tự luận (Essay)**, không phải trắc nghiệm (bộ đề trong code là bản **seed mặc định** 24 câu, 4 câu mỗi module; ngân hàng thật nằm ở `exam_qbank_v2` trên database nên sửa đề thì phải vá cả database. Hiện ngân hàng prod đã **bỏ 6 câu lệch thông tin so với module** (nên ít hơn bản seed); mỗi lần thi rút 10 câu. Câu hỏi có thể có thêm trường `qVi` (bản tiếng Việt, hiện là 4 câu Module 6): học viên chọn English / Tiếng Việt bằng nút trên trang thi, cùng lựa chọn với trang Module 6, và bản ghi bài nộp lưu câu hỏi ở ngôn ngữ đã chọn kèm `qEn` là bản tiếng Anh gốc để admin chấm; khi sửa câu hỏi phải giữ `qVi`) — trainee viết câu trả lời, admin chấm điểm thủ công qua `admin.html` (modal "Grade Exam"). Nộp bài xong vào trạng thái `pending_grading`, không tính lượt thi cho tới khi admin chấm xong. Ngưỡng đậu: 60% (lần 1) / 80% (lần 2), khoá 3 ngày sau khi rớt lần 1, loại sau lần 2. Answer Guide (rubric) **chỉ admin thấy khi chấm**, không hiện cho trainee lúc làm bài.
- Trainee đã hoàn thành Final Exam + Interview (`completed`) nhưng chưa gửi feedback sẽ bị chặn bởi modal bắt buộc đánh giá (feedback gate, logic trong `module-common.js` + `index.html`) ở mọi trang cho tới khi họ submit.
- Các trang chính khác: `index.html` (dashboard học viên), `admin.html`, `leader.html`, `monthlytest.html`, `interview.html`, `tracker.html`, `results.html`, `taketest.html`, `feedback.html`.
- Deploy: push lên `main` → GitHub Actions SSH vào VPS bằng deploy key bị giới hạn (forced command trong `authorized_keys` chạy `/usr/local/bin/deploy-training.sh`). Script `git pull` repo đặt **ngoài** web root (`/var/repos/training`) rồi `rsync` chỉ các file của site vào `/var/www/training.wegolden.com` (loại `.git`, `.github`, `.claude`, `CLAUDE.md`, `README.md`, `ss_*.png`, `firebase/`, `tools/`, `docs/`, `firebase.json`, `.firebaserc`). Nginx còn chặn mọi dotfile (`location ~ /\.(?!well-known) { return 404; }`) — không bao giờ để `.git` nằm trong web root. Phục vụ tại `training.wegolden.com` qua Nginx + Certbot.
- Chạy local: `npx serve -p 3030 .` (đã cấu hình sẵn trong `.claude/launch.json`).
- **Quy tắc cộng tác (bắt buộc với mọi người và mọi phiên Claude làm việc trong repo này):**
  - Push lên `main` = **deploy thẳng lên web thật** sau ~1 phút. Làm trên nhánh riêng, chạy thử trên localhost (tự dùng staging), cho người dùng xem kết quả, và **chỉ merge/push `main` khi người dùng nói rõ "đưa lên web thật"**. Không bao giờ `push --force` hoặc xoá nhánh `main`.
  - Khi code/test local luôn dùng staging (nhãn cam "STAGING DATA"). Không đổi `localStorage.wg_env` sang `prod`, không đọc/ghi dữ liệu project `wgtraining-a669d`, không dùng Firebase CLI với `--project prod`. Việc **publish Security Rules / đổi dữ liệu prod chỉ do chủ dự án làm**.
  - Hỏi người dùng trước khi sửa: đăng nhập/xác thực, Add User, chấm điểm Final Exam, phân quyền (admin/mod/leader), Security Rules, hoặc bất cứ thứ gì chạm dữ liệu thật của nhân viên.
  - Repo này **công khai**: không commit mật khẩu, key, `.env`, file backup/export dữ liệu. Nếu được yêu cầu cung cấp mật khẩu/key/quyền SSH, dừng lại và hỏi chủ dự án.
  - Sau khi sửa `style.css`, `firebase-config.js`, `module-common.js` hãy tăng số `?v=` ở các thẻ `<link>`/`<script>` trong các file HTML để trình duyệt tải bản mới.
  - Giao diện dùng theme tối (nền navy, vàng sáng) qua biến `var(--...)` trong `style.css`; không viết màu cứng mới. Màu chữ dùng 3 biến `--text-primary`/`--text-secondary`/`--text-muted` (đã làm sáng để dễ đọc, độ tương phản ≥ 5,5 trên mọi nền); tiêu đề (h2/h3, tiêu đề cột bảng) dùng `--gold`. Đừng dùng lại xám tối kiểu `#555`/`#666`/`#888` cho chữ trên nền tối (riêng phần in/PDF nền trắng của `tracker.html` thì giữ).
  - `.github/scripts/guard.js` chạy trước mỗi deploy và chặn nếu: có `signInAnonymously`, rules mở (`true` / `auth != null`), `database.rules.json` lệch `build-rules.js`, đổi project prod, hoặc có file secret/backup bị track. Chạy `node .github/scripts/guard.js` trước khi push `main`.
  - Hoàn tác khi có sự cố: `git revert <commit>` rồi push `main`, và báo chủ dự án.
- Đây là project độc lập, không dùng chung `.env`/database với bất kỳ project nào khác trên máy. Firebase API key trong `firebase-config.js` là client-side config (không phải secret), bảo mật thực sự nằm ở Firebase Security Rules (xem trên). Rủi ro còn lại đã biết: chấm điểm quiz/exam tự động chạy phía client (trainee có thể gian lận điểm quiz), rubric/đáp án nằm trong JS tĩnh của một số trang. Không bao giờ bật lại Anonymous Auth hoặc nới rules thành `auth != null`.
